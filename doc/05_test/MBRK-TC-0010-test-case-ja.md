# TC-0010 スマートフォンの画面に合った大きさで遊ぶ

- 対象：[MBRK-US-0010](../02_requirements/MBRK-US-0010-user-story-ja.md)
- 根拠の版の見直し（v1.2、2026-10-26）：GUI-0003 v1.3・TD-0003 v1.2（結果パネルの間は操作空間を出さず、ゲーム領域の大きさは変えない）は TC-0007-14 で確かめている。GUI-0003 v1.4 は代替テキストの名前だけで、この TC には関わらない。確認 ID は変えていない
- テストファイル：`tests/layout.test.ts`、`e2e/layout.spec.ts`（両プロジェクト）

| 確認 ID | 確かめること | 種類 | 手順・入力 | 期待結果 |
| --- | --- | --- | --- | --- |
| TC-0010-01 | 表示サイズの計算（§2.1） | 単体 | `computeDisplaySize` に GUI-0003 §1.2 の 4 つの画面（操作空間ありは `controlsHeight` 160、なしは 56） | 343 × 457、288 × 384、380 × 506、448 × 597。あわせて v1.1 までの値（操作空間なし）で 375 × 548 → 339 × 452 |
| TC-0010-02 | 最小・最大 | 単体 | 幅 200 の画面、幅 1920 × 高さ 1080 の画面 | 288 × 384、448 × 597 |
| TC-0010-03 | 1 画面に収まる（§12.7-1） | E2E | 各プロジェクトで START | 横スクロールなし（`scrollWidth ≤ clientWidth`）。Canvas・操作空間・一時停止ボタンの外形が表示領域の中 |
| TC-0010-04 | キーボードで縮まない（§12.7-2） | E2E | 結果パネルを出す → 表示領域の高さだけ 300 縮める → 幅も変える | 高さだけのときは Canvas の大きさが変わらない。幅が変わると計算し直す |
| TC-0010-05 | 44 px 以上（§12.7-3） | E2E | タイトル・プレイ・結果・ランキングの各画面で、すべての `button`・`input` の外形を測る | 幅・高さとも 44 以上 |
| TC-0010-06 | 高密度画面（§2.1） | E2E | `deviceScaleFactor` 2 のプロジェクトで Canvas を調べる | `canvas.width = CSS の幅 × 2` |
| TC-0010-07 | 向きを変えたら合わせ直す | E2E | 表示領域を 375 × 667 → 667 × 375 に変える | Canvas の大きさが計算し直される |
| TC-0010-08 | 横向きの案内（§8.1） | E2E | 667 × 375 でプレイ画面 | 「縦向きでのプレイをおすすめします」が見える。375 × 667 では見えない |
| TC-0010-09 | 実機の見た目 | 手動 | iPhone（Safari とホーム画面のアプリ）・Android で開く | ゲーム領域がくっきり表示される（ぼやけない）。ノッチ・ホームバーに内容が重ならない。画面に収まる |
