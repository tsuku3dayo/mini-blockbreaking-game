## 2. 確認結果（自動テスト・2026-10-23）

`e2e/keyboard-mouse.spec.ts`（pixel7・small の両プロジェクト）。時計は `page.clock` で止め、`runFor` で進めた。

| 確認 ID | 確かめたこと | 結果 |
| --- | --- | --- |
| TC-0008-01 | マウスで 100 → → を 0.5 秒で約 310 → マウスで 400。最後に使った入力に従う | 成功 |
| TC-0008-02 | D を 0.5 秒で右に約 210、A を 0.5 秒で左に約 210 | 成功 |
| TC-0008-03 | 単体（TASK-0005）に加え、E2E でも ← と → の同時押しで動かないことを確かめた | 成功 |
| TC-0008-04 | `repeat: true` の Space だけでは発射しない。続けて普通の Space で発射 | 成功 |
| TC-0008-05 | ボタンを押さずに動かすと追従し、ゲーム領域の左の外では 40 | 成功 |
| TC-0008-06 | 押して 30 px 動かして離しても発射しない。その場でクリックで発射 | 成功 |
| TC-0008-07 | プレイ中の ←・→・Space の `keydown` が、すべて `defaultPrevented` | 成功 |
| TC-0008-08 | マウスでプレイ中は Canvas の `cursor` が `none`、一時停止中は `none` でない | 成功 |
| TC-0008-09 | → を押したまま `window` の `blur` を送ると、それ以上パドルが動かない | 成功 |

- 「約 310」「約 210」の判定は、キーを押した・離した時刻とフレームの区切りのずれを見込んで 3 ステップ分（10.5 px）の差まで許した（最初は 2 ステップ分で、7.0000036 px の差で 1 回失敗したため）。直したあと 3 回繰り返して 54 件すべて通った。
- 単体 57 件・E2E 102 件、`npm run verify` は成功。
- 実装（`src/input.ts`）：← → A D を `event.code` で判定し、押している間 `dir` を出す（両方押しは 0）。キーで `source = keyboard`、ポインタを動かすと `source = pointer`。← → Space は発射前・プレイ中・一時停止中に `preventDefault()`。`keyup` はフォーカスの場所によらず離した扱いにする（押したままにならないように）。一時停止・`blur` では左右キーと指の追従をすべて離した扱いにする（中断（`pointercancel`）では指だけ）。マウスのボタンなしの追従とカーソルを隠す処理は TASK-0006 で入れたものを確かめた。

PR #33 の CI（`check`・`e2e`）は緑。2026-10-23 にマージ。

- 手動の確認は、オーナーのパソコンのキー配列だけで行った。ほかの配列（英字配列など）では確かめていない。
- フォーカスが入力欄にあるときにキーをゲームに渡さないことは、プレイ画面に入力欄がないので、E2E では確かめていない（ボタンにフォーカスがあるときは、TASK-0011 から同じ判定で渡していない）。
