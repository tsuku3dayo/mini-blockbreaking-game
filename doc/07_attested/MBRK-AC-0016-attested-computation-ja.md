そのほか：

- 単体 86 件・E2E 143 件（TC-0013-08 は small だけで流すので pixel7 は 1 件スキップ）、`npm run verify` は成功。
- TC-0013-06 は、テストの作り方を 2 回直した。
  - 最初はかなの 12 文字で、各プロジェクトの幅のまま確かめた。手元の pixel7（幅 412）では名前が 157 px で、セル（260 px）に「（あなた）」と一緒に収まって切れず、失敗した。収まるときは省略しないのが設計どおりなので、作りは直していない。
  - 次に、全角の「Ｗ」12 文字に替えた。手元（Windows）では切れて通ったが、PR の CI（Linux）では両プロジェクトとも切れずに失敗した。フォントが違い、文字の幅が狭かったため。
  - どのフォントでも切れるよう、このテストだけ幅を 320 に狭めた（名前に使える幅は約 97 px）。名前はかなの 12 文字に戻した。仕様で対応する最小の幅は 375 なので、320 は「必ず切れる状態を作る」ためだけに使っている。
  - そのため、幅 375・412 で実際に名前が切れるかどうかは、端末のフォントによる。
- スクリーンショット（375 幅、12 文字の名前 10 件、3 位が自分の記録）：GUI-0005 §1 の形（BACK と見出しのバー、列の見出し、1〜3 位の強調、2 段の行、自分の記録の背景と左の帯、名前の省略と「（あなた）」、右寄せのスコア）。横スクロールなし。
- 実装：
  - `src/ranking-view.ts`：開くたびに `loadRanking()` → 表・0 件・読み込み失敗のどれか。順位は保存の並び順の連番。名前は `textContent`、`title` に全文。
  - `src/format.ts` の `formatDateTime`：ロジック層では `Date` を使わない決まりなので、ISO 文字列から 1970 年からのミリ秒を計算し、`Intl.DateTimeFormat`（`ja-JP`、24 時間制、`timeZone` を省くと端末のタイムゾーン）に渡す。
  - `index.html`：ランキング画面の固定の 0 件表示をやめ、`#ranking-content`（表などを入れる場所）と `#ranking-backup`（TASK-0021 の場所、隠してある）にした。`main.ts` は画面の初期化でランキングを読み直す。
  - `src/style.css`：表（`table-layout: fixed`、順位 48・スコア 72）、自分の記録の背景（`color-mix` で `--accent` の 12%）と左の帯、名前の省略。

PR #37 の CI は、最初の push で TC-0013-06 が失敗した（上のとおりフォントの違い）。テストを直した push で `check`・`e2e` とも緑。2026-10-25 にマージ。

## 3. 確認できなかったこと

- 記録のバックアップ（書き出し・読み込み）の欄は、場所だけで中身はない（TASK-0021）。
- スマホで名前を長押しして `title` の全文を見られるかは、実機で確かめていない（ブラウザによって出ないことがある）。
- 自分の記録の背景に使った `color-mix()` は、古いブラウザ（iOS 16.1 以前など）では効かず、背景が付かない。左の帯と「（あなた）」の文字は出るので、見分けはつく。
- 画面を開いたときの読み上げは、読み上げの仕組みがまだないので入れていない。
- iPhone で長い名前が省略記号で切れる様子と、自分の記録の背景色は、確認の手順に入れていない（ランキングに出ることと残ることだけ）。
- Android の実機では確かめていない（端末がないため）。
