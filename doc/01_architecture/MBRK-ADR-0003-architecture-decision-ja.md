# ADR-0003 ゲーム領域の描画に Canvas 2D を使う

## 状況

仕様書 §2.2 は、毎フレーム盤面全体を描き直すこと、高密度画面でぼやけさせないこと、表示を 3:4 で拡大縮小することを求めている。§10 はスマートフォンでの 60 fps を求めている。描く物は四角形 40 個・角丸の四角形・円・文字だけで少ない。

## 決定

ゲーム領域は Canvas 2D で描く。論理座標（480 × 640）で描き、`devicePixelRatio` に合わせた実ピクセルの大きさのキャンバスに拡大して描く。タイトル・結果パネル・ランキング・ボタン類は DOM で作る（キーボード操作・フォーカス・読み上げを標準の部品で満たすため）。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. Canvas 2D（採用）** | 毎フレームの描き直しが軽い。座標の拡大縮小が簡単。ブラウザ標準 | 中身が支援技術から見えないので、代替テキストと読み上げを別に用意する |
| B. DOM（要素を動かす） | 要素ごとに調べやすい | 毎フレーム 40 個以上の要素の位置を変えると重くなりやすい |
| C. WebGL | 大量の描画に強い | このゲームには過剰。コードが増える |
| D. SVG | 拡大縮小がきれい | 毎フレームの更新は Canvas より重い |

## 結果

- 良い点：描画が軽く、スマートフォンでも 60 fps を狙いやすい。
- 注意点：Canvas の中身は E2E で直接読めない。E2E では、ゲームの状態を画面の DOM（HUD と同じ値を持つ読み上げ領域・結果パネル）や、テスト用に公開する状態で確かめる（方法は 05 テスト戦略で決める）。
