# ADR-0005 効果音を Web Audio で合成する

## 状況

仕様書 §8.7 は 8 種類の効果音、オン / オフ設定、オフライン動作、鳴らせない環境でもゲームを止めないことを求めている。§10 は鳴るまでの遅れを 50 ミリ秒以内の目安にしている。ブロックの音は行ごとに高さを変える。

## 決定

Web Audio API で、オシレーターと音量の変化を組み合わせて、出来事のたびに音を合成して鳴らす。音声ファイルは持たない。

- `AudioContext` は最初のタップ・クリック・キー入力のときに作る（または再開する）。
- 作れない・失敗したときは、以後何もしない（例外を外に出さない）。
- 一時停止・画面の非表示・オフにしたときは、鳴っている音を止める。

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **A. Web Audio で合成（採用）** | ファイルなしでオフラインに強い。音の高さを行ごとに変えやすい。ライセンスの心配がない。`simple_shogi` と同じ | 音作りをコードで行う |
| B. 音声ファイル + `<audio>` | 音作りが自由 | 鳴るまでの遅れが大きく、同時に鳴らしにくい。ファイルの用意とライセンス |
| C. 音声ファイル + Web Audio | 遅れが小さい | ファイルの用意とライセンス。キャッシュの対象が増える |

## 結果

- 良い点：オフラインで確実に鳴り、遅れも小さい。
- 注意点：iPhone のマナーモードでは鳴らないことがある（ブラウザの仕様）。手動テストで確かめ、「確認できなかったこと」に残す。単体テストでは、効果音の間引き（どの音を鳴らすか）までをロジック層で確かめ、実際の音は E2E のイベントと手動テストで確かめる。
