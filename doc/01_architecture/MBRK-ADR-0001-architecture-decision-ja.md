# ADR-0001 サーバーを持たず、ランキングを端末内に保存する

## 状況

仕様書 v1.0 は、全プレイヤー共通のランキングをランキングサービス（API + DB）で持つ前提だった。一方、手本にする `simple_shogi` はサーバーを持たない静的な PWA で、GitHub Pages で公開している。共通ランキングを持つには、サーバーと DB の用意・運用・費用、改ざん対策、個人情報（名前）の扱いが必要になる。

## 決定

サーバーを持たない。ランキングは端末（ブラウザ）の `localStorage` に上位 10 件まで保存し、その端末で遊んだ記録だけを扱う。アプリ全体を静的な PWA として GitHub Pages で配信する。（2026-10-23 オーナー決定、仕様書 v1.1 に反映済み）

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| A. 静的フロント + 自前の API・DB | 共通ランキングを実現できる。仕様書 v1.0 どおり | ホスティング・DB の運用と費用。オフラインで登録できない。`simple_shogi` の構成から外れる |
| B. BaaS（Supabase 等） | サーバーのコードが減る | 外部サービスへの依存。仕様書 v1.0 の API の形に合わせにくい |
| **C. 端末内ランキング（採用）** | 運用・費用がない。完全にオフラインで動く。個人情報を外に出さない | ほかの人とは競えない。ブラウザの都合で記録が消えることがある |

## 結果

- 良い点：構成が `simple_shogi` とそろい、サーバー・DB・API の設計とテストが不要になる。
- 注意点：記録が消える問題には、記録の書き出し・読み込み（仕様書 §9.6）で備える。名前とスコアの検証は、画面での入力とファイルの読み込みの両方で同じ規則を使う。
- 将来、共通ランキングが必要になったら、新しい ADR で見直す。
