# システム構成（system-architecture）

技術の版と道具は [MBRK-TS-0001](MBRK-TS-0001-technology-stack-ja.md)、判断の理由は ADR（MBRK-ADR-0001〜0008）を参照。

## 1. 全体像

**サーバーを持たない、ブラウザだけで動く PWA**（静的サイト）。ゲーム・ランキング・効果音・保存は、すべて端末の中で処理し、外部への通信はない（[ADR-0001](MBRK-ADR-0001-architecture-decision-ja.md)）。構成は `simple_shogi` と同じ（[ADR-0002](MBRK-ADR-0002-architecture-decision-ja.md)）。

```
GitHub (tsuku3dayo/mini-blockbreaking-game)
  │ main への push
  ▼
GitHub Actions ──lint / 単体テスト / build / PWA 検査 / E2E が通ったら──▶ GitHub Pages（静的配信）
                                                                          │ https://tsuku3dayo.github.io/mini-blockbreaking-game/
                                                                          ▼
┌─────────────────────────────── ブラウザ / ホーム画面アプリ ───────────────────────────────┐
│ index.html + public/boot.js（起動の見張り・復旧）                                          │
│                                                                                            │
│  画面層（DOM・Canvas・音・入力）        ロジック層（DOM に触れない純関数）                 │
│  ┌──────────────────────────┐          ┌──────────────────────────────────┐              │
│  │ 画面の切替え（タイトル /  │          │ ゲーム：状態・1 ステップの更新・  │              │
│  │ プレイ / 結果 / ランキング）│ ──入力──▶│   衝突・速度段階・スコア          │              │
│  │ ゲームループ（rAF）       │ ◀─状態・─│ ループの時間計算（蓄積器）        │              │
│  │ 描画（Canvas 2D）         │   出来事  │ ランキング：名前検証・順位・上位 10│              │
│  │ 入力（ポインタ・キー）    │          │ バックアップ：形式・検証・移行    │              │
│  │ 効果音（Web Audio 合成）  │          │ 表示サイズの計算                  │              │
│  │ 読み上げ（aria-live）     │          └──────────────────────────────────┘              │
│  └──────────────────────────┘                                                              │
│                                                                                            │
│  基盤：保存（localStorage）・PWA 更新ボタン・インストール方法の説明                        │
│  Service Worker（Workbox）：全ファイルをキャッシュし、オフラインで起動                     │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. 構成要素

ファイルの分け方の詳細は 04 詳細設計で決める。ここでは役割の単位を決める。

### 2.1 ロジック層（DOM に触れない純関数。Vitest で単体テスト）

| 要素 | 役割 | 仕様書 |
| --- | --- | --- |
| パラメータ | 仕様書 §11 の数値を 1 か所に集める | §11 |
| ゲーム状態 | パドル・ボール・ブロック・得点・経過時間・速度段階・状態（発射前 / プレイ中 / 一時停止 / クリア / ゲームオーバー） | §3、§7 |
| 1 ステップの更新 | 「今の状態 + 入力 → 次の状態 + 出来事の一覧」を返す。出来事は発射・パドル・壁・ブロック（行）・加速・クリア・ゲームオーバー | §5.2 |
| 衝突判定 | 円と矩形・壁・パドル・ブロック・最小垂直成分の補正 | §5.4〜§5.9 |
| スコア | 時間ボーナス・合計・結果サマリ | §6 |
| ループの時間計算 | 実経過時間からそのフレームで進めるステップ数を求める（100 ms 上限・蓄積器） | §5.1 |
| 表示サイズの計算 | 画面の大きさから表示幅・高さを求める | §2.1 |
| ランキング | 名前・スコアの検証、順位の計算、上位 10 件への追加 | §9.3、§9.4 |
| バックアップ | 書き出す形式の組み立て、読み込むファイルの検証・移行 | §9.6 |
| 効果音の間引き | 1 フレーム内の出来事から、鳴らす音を決める（同じ種類は 1 回、クリア・ゲームオーバー優先） | §8.7 |

ロジック層は乱数・現在時刻・DOM を直接使わない（時刻は引数で受け取る）。これにより、仕様書 §12 の受け入れ基準の多くを単体テストで確かめられる（[ADR-0004](MBRK-ADR-0004-architecture-decision-ja.md)）。

### 2.2 画面層（DOM・Canvas・ブラウザ API の操作だけ）

| 要素 | 役割 |
| --- | --- |
| 画面の切替え | タイトル・プレイ・結果・ランキングの表示切替え、ページタイトル、初期フォーカス |
| ゲームループ | `requestAnimationFrame` で毎フレーム、ループの時間計算 → ステップを必要回数 → 描画。発射前・プレイ中だけ動かす。画面が非表示になったら一時停止 |
| 描画 | Canvas 2D に盤面・HUD・オーバーレイを描く。高密度画面に合わせる（[ADR-0003](MBRK-ADR-0003-architecture-decision-ja.md)） |
| 入力 | Pointer Events とキーボードを、ロジック層に渡す入力（左右・ポインタ位置・発射要求・一時停止）にまとめる。タップの判定、キーリピートの無視、スクロールの抑止 |
| 結果パネル | 結果の表示、名前の入力と登録、入力ガード |
| ランキング画面 | 上位 10 件の表、「あなた」の強調、書き出し・読み込み |
| 効果音 | Web Audio で音を合成して鳴らす。オン / オフ（[ADR-0005](MBRK-ADR-0005-architecture-decision-ja.md)） |
| 読み上げ | `aria-live` 領域にスコア・一時停止・終了を出す |

### 2.3 基盤

| 要素 | 役割 |
| --- | --- |
| 保存 | `localStorage` を `try/catch` で包む。キーはアプリ識別子で始める。版番号と移行。書き込みの成否を返す（[ADR-0006](MBRK-ADR-0006-architecture-decision-ja.md)） |
| PWA 更新 | Service Worker の登録と「更新」ボタン |
| インストール方法の説明 | iPhone / Android / パソコンの手順と「今すぐインストール」 |
| 起動の見張り（`public/boot.js`） | 起動に失敗したら、このアプリの Service Worker とキャッシュだけを消して読み込み直す |
| Service Worker | ビルド時に自動生成。全ファイルをキャッシュする |

## 3. 処理の流れ

### 3.1 1 フレーム

```
requestAnimationFrame(now)
  ├─ 入力：押下中のキー・ポインタ位置・発射要求を読む
  ├─ ループの時間計算：経過時間（最大 100 ms）を蓄積 → 進めるステップ数
  ├─ ステップ × n：1 ステップの更新（状態 + 入力 → 状態 + 出来事）
  │     └─ 状態が発射前・プレイ中以外になったら残りを打ち切る
  ├─ 出来事 → 効果音の間引き → 効果音を鳴らす
  ├─ 出来事 → 読み上げ（スコアが変わった等）
  ├─ 描画：盤面・HUD・オーバーレイ
  └─ クリア / ゲームオーバーなら：ループを止め、結果サマリを作り、結果パネルを出す
```

### 3.2 スコア登録

```
結果パネル：名前を入力 → ランキングの検証（入力中に即時）
  └─ REGISTER → 保存から記録一覧を読む → 順位を計算 → 10 位以内なら一覧に入れる
        → 保存（記録一覧・次の id・前回の名前・自分の記録 id）
        → 成功：「n 位で登録しました」/「ランキング外でした」、効果音
        → 失敗：「保存できませんでした」（再度押せる）
```

## 4. 保存データ

すべて `localStorage`。キーは `<アプリ識別子>-<名前>`（アプリ識別子は `mini-blockbreaking-game`、[ADR-0007](MBRK-ADR-0007-architecture-decision-ja.md)）。値は JSON。

| 名前 | 中身 | 仕様書 |
| --- | --- | --- |
| `schema` | 保存データの版番号（最初は 1） | §9.1 |
| `scores` | 記録一覧（上位 10 件） | §9.1 |
| `nextId` | 次に採番する id | §9.1 |
| `lastName` | 前回の名前 | §9.5 |
| `lastRecordId` | 自分の記録 id | §8.4 |
| `sound` | 効果音のオン / オフ | §8.7 |

遊んでいる途中のゲームは保存しない（仕様書 §7.2）。

| 項目 | 内容 |

## 6. 非機能要件への対応

| 要件（仕様書 §10） | 構成上の対応 |
| --- | --- |
| 60 fps | Canvas 2D に毎フレーム描き直す。描画以外の DOM 操作（スコアの読み上げ等）は値が変わったときだけ行う |
| 物理の安定性 | 固定タイムステップのロジック層。表示のフレームレートに依存しない |
| 入力の遅れ | ポインタ位置はイベントで受け取り、次のステップでパドルに反映し、そのフレームで描く |
| 効果音の遅れ | 音は事前に用意せず、出来事のたびに Web Audio で即座に合成して鳴らす |
| オフライン | Service Worker が全ファイルをキャッシュ。外部リソースを使わない |
| 通信・個人情報 | 通信する部品を持たない |
| 端末内保存の失敗 | 保存の読み書きは失敗してもアプリを止めない。登録は失敗を画面に出す |
